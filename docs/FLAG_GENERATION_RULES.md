# 通用旗帜转换与生成规则

旗帜优先恢复源存档中可解析的设计；证据不足时，按明确身份和源数据生成备用旗。生成结果不应标成历史原旗。休眠国家的释放旗帜另见[源核心说明](CONVERTER_SOURCE_CORES.md)。

## 原则与优先级

1. **身份先于地名。** 从源存档获取文化、政体、改革、成立来源、实际宗主关系。地名相同不意味着与现实国家、部族或现代行政区身份相同。
2. **原作纹章优先。** 查找保存的旗帜键、当前 TAG、定义 TAG，解析纹章常量、父纹章和素材；有源证据的时代、政体、改革、曾用 TAG 条件才参与变体优先级比较。未知王朝和领土条件不当作成立。
3. **可靠身份回退。** 源纹章不可恢复而已有经核对的 V3 身份时保留 V3 旗；不会仅凭 TAG 字母相同套旗。
4. **文化图案优先于泛用宗教符号。** 生成旗可复用 EU5 的贝珠带、土家白虎、苗族纹样、蒙古装饰、南美图案等。文化素材字典是跨战役规则，不是国家白名单；复用一枚素材不等于复原完整原旗。
5. **地理与生产需要源证据。** 根据源国家地点数和目标首都州沿海属性，识别“小型沿海国家”的海洋旗式候选；不把它直接称为严格的岛屿检测。按源 RGO 就业汇总物产，单项占比至少 45% 才记为主导物产；零就业或缺数据不猜测。有对应图案的物产可影响徽记，没有对应图案时保留文化/地域设计。
6. **政体决定旗式，不能凭空创造王朝。** 共和国可使用较清晰的几何旗底；文化织纹和贝珠带不套欧洲盾徽。君主制不会自动凭空获得某个历史王朝国徽。
7. **宗主关系决定角标。** 实际殖民地或公司保留动态宗主旗角标，并以宗主纹章色调形成家族风格；旗式包括海旗、地方盾旗和商贸旗。普通属国不因拥有宗主就被当作殖民地，独立国不加宗主角标。公司优先使用航海题材。

在证据决定的范围内，稳定哈希只决定布局、边饰等细节，不决定国家所属文化、宗教或宗主关系。全部生成旗检查重复、素材存在、旗面边界和角标遮挡。

## 已实现的输入接口

`tools/m3_flag_art.py`：

- `economic_features(countries, source_economy, coastal_states)`：接收任意战役的国家集合、源经济地点表和沿海州集合；不读取固定国家名或 TAG。
- `contextual_design(identity, color, country, src, colonial, region, company)`：文化、政体、来源数据及上述特征驱动的通用设计。
- `compile_design(design)`：输出 V3 原生纹章脚本。

`FlagExporter` 从 `world.flag_features` 获取可选源经济特征；没有这份数据时使用可证明的文化/地域信息，不推断特色产业。调用方应传入对应存档的源经济表，并核对来源哈希。

规则目前支持部分文化素材和部分物产图案；缺失项保留明确的地域回退。严密的全境海岸/岛屿识别、完整王朝与领土变体解释、游戏内动态纹章导出仍未实现，不把这些能力记作完成。

## 渲染规则

V3 本地 `jomini/gfx/FX/coat_of_arms/coat_of_arms_textured_emblem.fxh` 的彩色纹章规则为：底色 color1，绿色通道混合 color2，红色通道混合 color3，蓝色通道为明暗叠加。不能把三个颜色全部设为同色来处理复杂文化织纹。

编译器显式输出三个颜色；预览器使用同样的通道顺序。预览仍不模拟全部游戏渲染效果，灰色角标也是宗主旗占位，不是实机截图。

## 证据与验证边界

同名的现代旗帜不能直接当作架空战役的原旗。存档纹章管理器为空、定义缺失或条件无法求值时，报告保留原因，并区分源脚本旗、经核对的目标身份旗和程序生成备用旗。

验证应覆盖未知国家的通用设计、零就业不推断物产、文化图案分色、角标边界、重复旗及素材引用。修改渲染或生成规则后，还需在游戏中核对显示和缓存行为；静态预览不等于实机截图。

旗帜素材可能来自使用者本机游戏安装。生成工具的代码许可不等于这些素材可以随软件分发，见[许可说明](LICENSING.md)。
