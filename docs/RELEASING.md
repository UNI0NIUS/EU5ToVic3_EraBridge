# Release 准备与验收

当前版本：`v0.12.2-beta.1`，公开源码预览版。源码开放自行构建与社区测试，Windows x64 便携包仍为内部候选。安装包应作为 [GitHub Release 附件](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)上传；仓库保留源码和构建材料，不提交 ZIP 或游戏数据。

## 已整理的材料

- 使用说明、构建步骤、架构和转换规则统一收录于[文档索引](README.md)。
- [发布说明](releases/v0.12.2-beta.1.md)记录已有功能、适用版本和限制，区分已验证范围、已知问题和未覆盖的环境。
- `tools/prepare_release.py` 从已有本地构建生成独立暂存目录，收集依赖来源、可核实的许可文本、文件清单和 ZIP 校验值。
- 原有本地构建、游戏安装、规则包和项目目录保留原样。暂存目录使用空的游戏路径与候选路径设置。

## 生成内部候选

先按[构建说明](BUILDING.md)准备本地桌面构建，再在仓库根目录运行：

```powershell
python -X utf8 tools/prepare_release.py --app build/ConverterWorkbench --out build/release-preparation/v0.12.2-beta.1
```

输出目录必须是 `build/` 下尚不存在的新目录，且与输入目录分开。需要重跑时使用新名称，防止覆盖之前的检查证据。`--python-base` 可指定构建时使用的 Python 安装目录；默认取当前解释器的安装根目录。`--no-archive` 仅准备目录和报告，暂不压缩。

| 产物 | 用途 |
|---|---|
| `EraBridge-0.12.2-beta.1-windows-x64-INTERNAL/` | 含运行环境与规则配方；首次使用从本机游戏生成资源，仅供内部验收 |
| 同名 `.zip` | 内部传递的候选副本，不上传到公开 Release |
| `SHA256SUMS.txt` | 核对 ZIP 是否完整 |
| `release-readiness.json` | 来源提交、工作区状态、输入二进制摘要、排除项和未完成条件 |
| 候选内 `build_manifest.json` | 每个打包文件的 SHA-256，不含清单自身 |
| 候选内 `licenses/runtime-inventory.json` | 运行库文件与包缓存或 wheel RECORD 摘要的来源对应，以及未匹配项 |

依赖来源按实际文件摘要核对，不能只看包名。例如，当前环境中的 NumPy 已由 pip 安装为 2.3.1，而 conda 元数据仍记为 2.3.5；脚本另用 wheel 的 RECORD 摘要确认 pip 文件，仍未匹配的文件不会被标成已确认来源。运行包原有的 Python、NumPy、Pillow 许可和元数据保留；缓存中能确认的依赖许可另行收集。收齐文本不代表已完成分发条款审查。

准备脚本始终将 `ready_for_publication` 设为 `false`。它只生成检查材料，不负责批准发行，也不会创建标签、上传附件或发布 Release。

MIT 允许独立修改和再发布上游代码，但不能据此判断游戏素材或所有依赖均可分发。来源及上游贡献政策见[许可说明](LICENSING.md)。

独立机器准备和脚本命令见[独立验收](ACCEPTANCE.md)。脚本不会把限制 PATH 的开发机检查标记为干净 Windows 验收。

## 便携附件的准备顺序

1. 确认依赖分发许可，披露上表尚未完成的测试，并从最终提交重建候选。先核对包内无存档、密钥、个人项目、日志、默认游戏路径或开发缓存。
2. 在独立测试目录验证带空格及中文的路径。记录是否仍依赖本机 Python、PATH、游戏安装或旧缓存；移目录检查与干净机器测试分别记录。
3. 核对 ZIP 中每个文件与清单一致，验证 SHA-256，并在发行说明中写明测试输入、游戏版本、通过范围和已知限制。
4. 本次先公开不含便携附件的源码预览版，保留 **Pre-release** 标记。后续便携版使用新标签并关联实际构建提交，添加 ZIP、`SHA256SUMS.txt` 和必要通知；检查下载文件与本地候选相同。
5. 确认草稿中的附件、文字和版本一致后发布。未来版本重复构建和验收，不直接覆盖旧版本附件。

正式附件计划命名为 `EraBridge-0.12.2-beta.1-windows-x64.zip`。这只是命名约定；当前带 `INTERNAL` 的候选不能通过改名直接变成发行包。GitHub 自动附带的 Source code ZIP/TAR 是源码快照，不包含便携运行环境，也不等同于安装包。
