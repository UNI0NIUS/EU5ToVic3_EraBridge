# EraBridge 桌面工作台 0.12.2

**简体中文** · [English](CONVERTER_WORKBENCH.en.md)

从 beta.3 起，可在主窗口“语言 / Language”切换中英文；导入和导出另有“游戏显示语言”选择。对应资源随模组保留，实际游戏显示由 V3 的语言设置决定。生成 `.v3` 需启用输出模组、新开战役后在游戏内保存。详见[多语言支持](LOCALIZATION.md)。

[文档索引](README.md) · [发布准备](RELEASING.md)

本文适用于 beta.3 Windows x64 便携版与完整本地构建。便携包已作为社区预发布版提供；首次使用仍需从自己的游戏安装和基准存档生成规则。开发机检查已完成，独立 Windows 与游戏内验收仍有未覆盖项，见[验证记录](PUBLICATION.md)。源码构建见[构建说明](BUILDING.md)。

工作台使用 Windows 原生桌面窗口，提供地图检查、人口与耕地调整、地区编辑和模组导出。完整本地构建包含 Python 运行环境，启动时无需浏览器或本地 HTTP 服务。

## 启动与流程

发行版完整解压后双击软件根目录 `EU5Converter.exe`。源码本地构建可双击项目根目录 `Open-ConverterWorkbench.cmd`，或 `build/ConverterWorkbench/EU5Converter.exe`。完整保留软件目录，不能只复制一个 EXE。使用窗口右上方“退出”或关闭按钮退出。转换中退出会询问是否停止转换；保存、导出等操作会在完成后退出，避免留下半写入文件。退出后再次启动会恢复上次的项目。

“打开项目 / 结果”可以选择已有候选包。目录必须包含 `package_report.json`，其指向的模组文件必须与清单哈希一致。保存项目之后，可以从列表恢复参数、合并决定和修订记录。

首次使用先点击“准备转换规则”。在 Victoria 3 1.13.11 中禁用全部模组，新开 1836 年战役，保持暂停并立即保存。选择 EU5 安装目录、Victoria 3 安装目录或 `game` 目录，以及该 `.v3` 存档。程序检查开局日期、版本和基准人口，再从本机安装生成身份定义、本地化和图标。仅凭存档没有模组字段不能证明未启用模组，准备基准时仍须自行检查启动器。

规则写入工作区的新目录，完成后自动记住路径；失败时保留错误信息，不覆盖已有规则。当前配方对应 EU5 1.3.11、V3 1.13.11，地图或所引用资源不匹配时会停止，不能跳过校验继续使用。

“导入 EU5 存档”接受游戏 `.eu5` 存档，包括压缩、二进制和已解码文本。“浏览…”打开绑定到主窗口的 Windows 文件或文件夹对话框。填写 EU5 安装目录、V3 的 `game` 目录、规则包 `manifest.json`。输入路径会在下一次导入时恢复。

模组目录留空时，自动按存档记录的加载顺序匹配当前 Steam 库创意工坊内的同名、同版本模组。缺失或匹配不唯一会提示原因；也可以每行填写一个具体模组根目录。自动匹配结果保存在任务的 `source/resolved_mods.json`。不会自动下载模组，也不保证支持所有第三方模组规则。转换完成后自动进入地图调试。

加载和转换在后台执行，窗口底部显示当前进度。操作失败会弹窗说明原因并保存日志；原生导入失败会显示 `log.txt` 中的具体原因，例如缺失模组，而不是只显示退出码。

新存档流程独立执行导入、人口/文化/宗教/识字率提取、地理补全、国家和政治规则、经济、军队/舰队、供应链、耕地及开局战争。国家归属和人口读取本次存档。规则包只提供地理对应、身份映射、定义资源、经济政策和明确的空人口模板规则，不提供旧战役国家/人口/领土历史。

战争中的 `Declined`（拒绝参战）记录会保留在报告中，不加入交战阵营。对存档明确命名为 `AGRESSION_WAR_NAME`、但没有序列化战争目标的侵略战争，使用既有羞辱／边境预算规则作近似，并在 `war_mapping.json` 的 `limitation` 字段标明；不推断不存在的源领土诉求。其他无法识别的目标仍停止并报错。

未知二进制词元、未知文化或宗教、地图哈希不符、未解决荒地、尚未支持的战争目标等会中止转换，并将具体阶段、原因和日志保存到任务目录；失败目录不会作为已完成候选包展示。beta.3 复核中，1338 KNI 二进制存档仍因未知词元失败；通用输入接口不代表任意存档已支持。提交复现材料见[问题与存档指南](SUPPORT.md)。

## 参数与提醒

| 控件 | 默认值 | 含义 |
|---|---:|---|
| 人口系数 | 1.0 | 从本项目输入人口重新分配，不累乘；写入导出人口 |
| 耕地系数 | 1.0 | 调整各州总耕地，按最大余数法估算各国家份额；写入导出州定义 |
| 劳动力比例 | 25% | 仅用于风险估算 |
| 正式岗位招聘比例 | 75% | 仅用于正式建筑岗位/产能的规划情景 |
| 食物消费生活水平 | 10 | 读取游戏原生消费篮子；仅用于风险估算 |
| 低耕地 | **≤ 3** | 指国家在该州分得的耕地，不是地块数 |
| 严重失业缺口 | ≥ 25% | 估算岗位容量不足以覆盖的劳动力比例 |
| 食物供应缺口 | ≥ 20% | 按预计市场接入计算的有效食物缺口 |

低耕地、严重失业和食物不足各自触发提醒，可以同时出现。风险列表可搜索国家、所选语言的州名、州键和 TAG；地图提供国家、州界与地块、市场归属、耕地、失业、食物六种图层。点击列表或地图定位地区；拖动平移，滚轮或按钮缩放。左右侧栏可滚动，较小窗口也能使用底部按钮。

## 耕地、建筑与州界编辑

选中地区后点击“编辑耕地 / 建筑 / 地块”。“整州耕地”设置整个州的基础耕地总量，导出时再乘全局耕地系数，州内各国家按地块数比例分配。“分属地区建筑”可切换本州的不同国家，筛选建筑并输入等级；0 表示移除，自给建筑由剩余耕地自动形成。新增建筑使用所属国家可用的生产方式，不能凭空解锁技术。编辑兵营时同步营数；新增且没有现有兵种的地区配置基础步兵，海军建筑调整不自动增加舰船。

“整州耕地”中的“计算所需耕地”给出两档建议：当前所选地区退出严重失业提醒、岗位容量覆盖全部劳动力。显示整州应调到的基础耕地总量、新增量，以及所选地区分到多少耕地和预计失业缺口，可一键填入后预览。计算包括全局耕地系数、州内地块分配、已有农业建筑占地、正式岗位与自给农业生产方式。建议是保证模型容量足够的参考值，不声称是严格最小值；它针对当前地区，也不等于实际招聘、工资或收入改善。

“地图地块 / 州界”支持多选地块后转入相邻地区，可同时改变所属国家和所属州。也可以在主地图 Ctrl + 点击选择同一地区的地块，再打开编辑器。原州须保留至少一个地块，不支持删除州定义或绘制新的像素地块。转移不会增减世界总人口或建筑等级；因为候选包只有地区级人口和建筑数据，拆分按地块数比例以最大余数法分配，之后可单独改建筑数量。州界改变会同步地块列表、州历史、人口、建筑和军队驻地；被移走的城市等地图标记移到本州剩余地块。耕地与资源总量不会随州界自动转移，可用整州耕地设置重新调整。

每次编辑先显示影响预览，确认后保存，并可逐次撤销。农业建筑超过可用耕地时显示风险，导出前须提高耕地或减少农业建筑。预览与导出使用同一套操作记录；原始存档和输入模组不会被覆盖。

食物计算包括自给农业，并从产出中扣除工业耗用；沿用既有经济规划规则，自给农民的 95% 口粮视为实物自给，失业家庭仍保留完整需求。按实际候选包的附属关系、市场协议和国家集团规则组成市场：读取集团身份与当前原则中的 `power_bloc_customs_union_bool`，普通集团不自动共享市场，`grant_own_market` 保留独立市场。具体集团及市场依据可在选中地区后点击“计算依据与局限”查看。

界面分别显示本地缺口、市场缺口和有效缺口。陆地连接（包括游戏定义的海峡）或两端有效沿海港口，以及本地基础设施容量，构成静态市场接入估算。只有预计能进入市场的产出和需求参与汇总；工业食物耗用按商品跨地区抵扣，剩余供给按需求比例分配，避免同一份食物重复补多个地区。失联地区保留本地风险。整合、迁都或外交关系变化后会重新计算市场。

这仍是产能情景，未模拟运输舰吨位、封锁、市场外贸易、价格、工资或真实招聘，也不是游戏引擎实测的市场接入值。**食物风险不等于实际已经发生饥荒，岗位缺口也不等于游戏运行后的实测失业率**。无法解析的产能或接入显示“未知”，不据此自动合并。

## 在地图上合并

选择来源地区，选择“当前州内的地区”或“整个国家”。目标可在相邻国家下拉列表中选择，也可点“从地图点选目标”再点击地图。

- 地区合并将同一州内该国家的完整地区交给另一相邻国家，转移地块、人口和建筑，不改变原有州边界。如果这是来源国最后一个地区，自动按整国合并同步国家关系。
- 国家合并转移来源国全部地区，保留目标国身份、法律和技术。居民的文化、宗教和人口继续保留。
- 合并必须真实陆地相邻；跨海跳转不作为陆地相邻。
- 转移首都地区时，若来源国仍存在，迁都到剩余人口最多的州（再按地块数和州键确定）；预览列出迁都结果。国家合并重定向外交关系，清除自身关系与内部条约，去除重复关系，优先保留接收国原有附属与组织关系，并避免附属环。生产方式冲突统一为接收国可用方式；建筑本身未解锁时仍明确提示。
- 战争双方因合并重叠，或目标地区已不存在时，结束该场开局战争并在确认前列出；其余有效战争保留并重定向参与者。这是玩家编辑政策，不是重新推断 EU5 历史。上述调整同时写入 `package_report.json` 的 `adjustments`。
- 合并不创造耕地、工作或食物。界面重新计算合并后的地区；其他州的工作不能自动解决本州失业。

“确认合并”保存本项目的决定并重新计算风险。可以逐次撤销，也可以恢复初始方案。每次修改检查修订号并保存历史；输入文件发生变化时要求重新载入，防止旧决定套入另一张地图。

## 批量整合与流畅性

战略地区采用所选游戏安装中的定义（多个州组成），并提供对应地图。全图可逐州或逐战略地区处理，也可只处理当前州、当前战略地区。战略地区的接收国按整个战略地区各国地块总数确定，允许跨州转移所属国家，包括原来未持有该州的接收国；州界保持原样。并列仍按 TAG 排序。预览会列出每个转移地区的筛选原因、接收国家及两种食物缺口。

缺粮条件分为“市场缺粮”“本地缺粮”“接入后仍缺粮”，分别使用共同市场整体缺口、本地生产与需求缺口、结合预计接入后的有效缺口。三者可独立勾选，另可勾选严重失业，采用任一条件符合的规则。未知值不选入。本地缺粮而市场充足的地区不会仅凭本地缺口入选“市场缺粮”批次。行政整合本身不创造食物。

地图分别提供“市场归属”“市场食物缺口”“地块本地食物缺口”“接入后食物缺口”。前者颜色只代表归属。市场食物图同市场同色；本地图在地块边界上绘制所属分属地区的本地数据，不假称存在单地块历史粮食统计。缺口图以绿表示无缺口、黄表示低于提醒阈值、红表示达到提醒阈值、灰表示未知。

左侧“批量整合风险地区 / 州…”提供按州或战略地区整合的全图和当前范围。目标固定为操作前在相应层级地块最多的国家，并列时按 TAG 排序确定；已经属于目标国的地区保持原状。批量整合允许所选范围内的地区之间不直接接壤，单独手动合并仍保留相邻规则。

确认前列出应用范围、迁都和政治调整。遇到未解锁、条件建筑或生产方式不兼容时，预览会列出每处建筑类型、等级和原因，并提供“保留建筑，跳过冲突地区”和“自动拆除冲突建筑后整合”两种选择，默认保留。自动拆除只移除清单中的冲突建筑，其余建筑随领土转移；拆除清单同时写入导出报告。整批作为一个操作应用，一次撤销同时恢复领土和拆除的建筑。全部地区都有冲突时，保留方案不能确认空操作，可选择拆除方案或取消。若一个国家的最后领土分入多个国家，其外交关系由接收它地块最多的国家继承，预览会说明。批量整合不保证消除食物或就业问题；同一市场的行政合并可能只改变地区统计。

补建与快速整合分开进行。整合完成后，进入“地图地块 / 州界”，只选一个地块，点击“按所选单地块计算补建”。选择一种生产建筑、食物或就业目标及新增等级上限，使用当前市场与地区数据计算：按地块数均分地区需求，用新增一级的边际改善估算等级，并重新计算建议方案的实际静态影响。界面列出新增等级及地区食物、失业缺口的前后变化，确认后才写入。受当前科技、耕地、固定资源、沿海条件、地区劳动力和单次上限约束；条件未知或新增一级反而恶化指标时不会生成自动方案。农业、固定资源、制造业以外的特殊建筑仍可手动编辑。

V3 建筑属于分属地区，因此补建数量汇总到该地块当前所在地区。地块级人口和需求是均分估算，不是历史记录；补建不保证供应链投入充足或盈利，也不会在合并时自动补全整个国家。

州数据改为一次分组重建，连续编辑增量重放；预览确认和撤销复用已算结果。地区高亮使用独立后台任务，连续点击只保留最后一次结果，不再占用整个平台的忙碌状态。点选目标模式可按 Esc 退出，点击非目标地区也会退出并正常选择，合并完成后自动选中接收地区。

## 批量削减人口

左侧“削减人口 / 批量调节…”支持当前分属地区、州、国家、战略地区和全图。可筛选市场缺粮、本地缺粮、接入后缺粮或严重失业，也可处理范围内全部地区。按比例模式输入要削减的百分比；岗位模式按当前岗位容量估算剩余人口，未知岗位跳过。每个有人地区至少保留 1 人，文化与宗教按原比例以最大余数法分配；不改变地块、建筑和军队。

确认预览显示涉及地区、实际减少人数（包括全局人口系数）以及地区食物和失业缺口的前后变化。削减人口可能降低自给农业供给，也可能让已有建筑和军队缺人，不保证食物缺口消失。整批一次撤销恢复；原始存档和输入模组保持不变。

## 1337 指挥上限兼容修复

V3 1.13.11 的军衔收益由国家陆军、海军军衔影响倍率缩放。早期年份转换中，国家可能尚未研究提供该倍率的科技，导致有军衔却没有个人指挥容量。

转换器在原生倍率不大于零时提供基础补偿，数值取自游戏最小正科技增量（当前陆军 20%、海军 25%）。研究出原生倍率后自动移除补偿，不额外授予科技。新转换与工作台导出均包含这一处理。

脚本需要重启游戏加载：新战役在初始化时更新，旧存档在下一次国家月度更新时补齐。代码、脚本结构和数值规则已验证，游戏内个人面板仍需复核。

## 导出、文件与验证边界

导出时可自定义模组名称，支持中文，最多 120 个字符。名称写入启动器元数据、`.mod` 描述文件和导出报告；取消操作不创建输出。

导出始终创建新目录，回读核对人口总量、全部地块及所属州、地图州定义、首都归属、建筑等级及人口地区引用。耕地小于已有农业建筑占地、引用冲突等会阻止导出。输出包含：

- `eu5_converted/` 与 `eu5_converted.mod`：独立候选模组。
- `project.json`：参数和合并决定。
- `risk_report.json`：地区风险和计算假设。
- `package_report.json`：输入指纹、输出哈希和校验结果。
- `localization_verification.json`：所选语言的覆盖与文件格式检查。
- `README.txt`：所选输出语言的安装说明。

发行版通过 `EU5Converter.exe` 启动时，以下路径均相对于软件解压目录：

| 数据 | 位置 |
|---|---|
| 初次完整转换结果 | `data/runs/<时间戳-ID>/complete/` |
| 工作台再次导出 | `data/exports/<时间戳-ID>/` |
| 已保存项目 | `data/projects/` |
| 完整转换任务与日志 | `data/runs/` |
| 工作台错误 | `data/logs/` |

“打开输出目录”定位最近输出。源码启动默认使用 `.local/converter/`；指定 `--workspace` 时以指定目录为根。导出不会直接写入 Victoria 3 的 `mod` 目录。

模组需手动复制到 Victoria 3 用户的 `mod` 目录，并在启动器启用。应新开战役验证。软件不会自动安装或替换现有模组。静态检查和完整转换成功均不意味着已完成游戏内运行、经济平衡或长期稳定性验收。

规则包带有资源哈希。迁移电脑时，Victoria 3 基准开局文本仍须由本地玩家提供；`manifest.json` 的 `baseline` 与 `baseline_sha256` 必须相符。发行包不附带游戏本体、玩家存档或基准存档。
