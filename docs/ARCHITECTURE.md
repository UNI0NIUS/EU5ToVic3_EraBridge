# 开发架构

EraBridge 的桌面版由 C++ 存档导入器、Python 转换管线和 Tk 界面组成。C++ 负责读取与核查源存档；完整目标模组由 Python 分阶段生成。上游 C++ 目标世界实现仍有占位部分，不能将它单独视为桌面版的完整转换入口。

## 模块职责

| 入口 | 职责 |
|---|---|
| `EU5ToVic3/` | 源存档解析、导入审计和原生转换器基础设施 |
| `tools/converter_desktop.py` | Tk 窗口、地图操作、任务状态与错误展示 |
| `tools/converter_controller.py` | 界面与项目、转换、预览和导出之间的调用 |
| `tools/converter_pipeline.py` | 独立任务目录、子进程、阶段调度、取消与最终检查 |
| `tools/converter_source_*.py` | 通用地理、人口、政治、经济及完整候选构建 |
| `tools/converter_project.py` | 项目数据、文件摘要与持久化辅助 |
| `tools/build_converter_rules.py` | 冻结映射、配置、身份资源及来源摘要 |
| `tools/package_converter_app.py` | 收集本地运行环境、原生程序、代码和规则 |
| `tools/prepare_release.py` | 建立独立内部候选和发行核查材料 |

`config/personal/` 是沿用的目录名，包含通用规则以及部分旧战役配置。读取时需核对字段的适用范围；不能将整个目录视为任意新存档的默认配置。

## 转换流程

1. 检查存档、EU5 安装、Victoria 3 的 `game` 目录和规则清单，创建独立运行目录。
2. 核对规则文件摘要、两款游戏地图摘要及基准存档摘要；原生导入器解析输入并生成审计结果。
3. 从同一源存档提取国家、人口、文化、宗教、识字率、政治、经济、陆海军和战争数据。
4. 构建目标地理与国家，分配人口和身份，再生成法律、科技、经济、军队、供应链及开局战争。
5. 回读输出，检查人口、领土、引用和启动脚本；通过后生成完成包及哈希清单。

任务的规则快照与输入摘要用于追溯。失败时保留阶段、错误和日志，未完成目录不会作为成功结果。取消只终止该任务的进程及其子进程。

## 数据边界

| 数据 | 是否随源码提供 | 使用方式 |
|---|---|---|
| 转换代码、配置、应用图标 | 是 | 由仓库维护并纳入版本控制 |
| 游戏安装、玩家存档、基准存档 | 否 | 由使用者本机提供 |
| 完整生成规则及游戏衍生资源 | 否 | 由本地构建准备，发行前另核对来源 |
| 转换任务、编辑项目、导出模组、日志 | 否 | 写入工作目录，按任务或项目隔离 |

规则提供地理对应、身份映射和明确政策；国家归属与人口从本次存档读取。旧战役的国家 ID、人口历史和领土历史不能作为新存档的默认输入。共享资源更新应按身份键处理，避免覆盖战役事件翻译。

## 编辑与导出

工作台读取已校验候选，在项目中保存参数及操作记录。预览、确认、导出使用相同的操作逻辑，撤销恢复相应修订。输入指纹或修订号不匹配时要求重新载入，避免把旧决定应用到已变化的数据。

导出创建独立目录，重新检查人口、地块、所属州、首都、建筑及相关引用。地区转移与合并会按规则处理外交和战争，并在确认前展示影响；详细行为见[桌面工作台](CONVERTER_WORKBENCH.md)。

## 验证与扩展

增加转换规则时，应同时说明输入证据、适用条件、回退方式和不可表达的内容。对人口、领土、身份及建筑的修改需验证守恒或明确列出变化原因；未知信息不能当作条件成立。

单元测试验证确定性规则，回读检查验证输出一致性，游戏内测试验证引擎能否按预期运行。当前范围见[验证记录](PUBLICATION.md)。构建命令见[构建说明](BUILDING.md)，依赖与资源分发要求见[发布流程](RELEASING.md)。
